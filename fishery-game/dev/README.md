# 管理者（開発）版

進行を加速して、テストやバグ探しをするための版です。**製品版には入りません。**

## 仕組み
- 管理者機能は、`dev/admin.js` だけにあります。ゲーム本体（`../index.html`）には、含まれていません。
- `node dev/build-dev.mjs` が、ゲーム本体に `admin.js` を取り込んで、`dev/dist/index.html` を作ります。
  - 保存先のキーを別にします（`umikaze-fishery-dev-v1`）。製品版のデータとは、混ざりません。
  - タイトルに DEV を付け、画面の右上に赤い「DEV」を出します。
- 製品版のビルド（`app/` の `npm run build`）は、最後に `dev/check-prod.mjs` を実行します。管理者機能の目印が混ざっていたら、**ビルドが失敗**します。

## 使い方
```bash
node dev/build-dev.mjs        # 開発版を作る → dev/dist/index.html
node dev/check-prod.mjs       # 製品版に、管理者機能が混ざっていないか検査
```
画面の左下の赤い「DEV」ボタンで、パネルが開きます。数字は、検出した異常（エラーと不変条件の違反）の件数です。

| タブ | できること |
|---|---|
| 進行 | 日にちを進める（+1/7/30/100日）、お金・経験値・BPの付与、レベル・ランクの指定、券・デイリーの付与、経験値・売値の倍率 |
| 解放 | 全海域・全船、設備・施設・漁師を最大、図鑑の全登録、エリアのコンプ、魚箱の操作 |
| 釣り | 次に釣れる魚（種類・サイズ）の指定、主を必ず出す、アタリ即時、戦闘を自動で勝つ、糸が切れない、海域の変更 |
| プリセット | 序盤・中盤・終盤・全開放・まっさら をワンタップで読み込み、スロット3つに保存・読み込み。読み込む前の状態は、「控え」に残る |
| 調査 | 不変条件の検査（お金がマイナス・NaN・魚箱の上限超えなど）、保存→読み込みの往復テスト、主の診断、状態の一覧、ログ、保存データ（JSON） |

## 保存データを分ける（大事）
開発版で作った極端なデータが、本番のデータに混ざらないようにします。
- **Claude上のプレビュー**：開発版を、製品版とは**別のアーティファクト**として公開します。端末内もクラウドも、自動で別になります。
- **Androidアプリ**：開発版のアプリは、パッケージ名（例 `…umikazefishery.dev`）と、Firebaseのプロジェクトを分けてください。製品版のFirebaseには、つながないでください。

## 管理者パネルを出せる人
- Claude上のプレビューでは、アーティファクトの**持ち主だけ**に出ます（共有された人には出ません）。
- Claudeの外（ローカルでファイルを開いたとき）は、そのまま出ます。

## 自動テスト（CI）
`.github/workflows/fishery-game-tests.yml` が、`fishery-game/` を変更した push・PR と、毎週1回、自動で次を実行します。
1. `check-prod.mjs` … 製品版に管理者機能が混ざっていないか
2. `qa.mjs` … 機能ごとのシナリオテスト（経済・注文・大会・オスメス・色違い・最初の案内など）
3. `monkey.mjs` … 画面のボタンをランダムに押し続けて、エラー・「NaN」表示・不変条件の違反を探す

手元でも同じことができます：`cd fishery-game/dev && npm ci && npx playwright install chromium && npm run qa`
失敗したときは、そのときの開発版（`dist/index.html`）がワークフローの成果物として残ります。
